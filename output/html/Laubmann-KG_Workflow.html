Laubmann KG — how the workflow works

Alfred Laubmann's ornithological field diaries (34 volumes, 1917–1965) → a knowledge graph and a Darwin Core Archive. An LLM reads each diary entry; the code only checks form, applies reviewer corrections, links to authorities, resolves entities, and serialises to standards (ontology 0.6.0).

2 · Principle

  • The model decides content. Which bird, where, how many, sex, breeding evidence, absence, who observed, the entry's own date and place, and (0.5.0) vantage / microhabitat / time-of-day / viewing radius.
  • The code checks form. Enum membership, integers, dates, endpoints for travel legs, SHACL safety, authority links.
  • Nothing is fabricated. No default evidence, no placeholder call transcription, no injected behaviour; what the text does not say stays absent.
  • Reproducible. Temperature 0, responses cached by sha256(model, prompt); a prompt change is a full live run (~2–3 h).
  • Reviewable. Every exclusion, correction and uncertain link lands in a CSV with a decision column that feeds back on the next run.
  • Standards first. Ontology 0.6.0 remains Darwin-Core-first (as of 0.4.0): dwc:/dwciri:/dcterms:/prov:/skos:/gsp: wherever they exist, lkg: only for project-specific meaning; tests/test_ontology_alignment.py guards ontology ↔ emitter ↔ SHACL ↔ JSON-LD in both directions.

  • Two grouping superclasses (ArchivalUnit, EntryRecord) carry the hierarchy; every child node is dcterms:isPartOf its parent, every extracted record (travel legs included) prov:wasDerivedFrom its entry.
  • DiaryEntry is the DwC event; Observation is the DwC occurrence. Behaviour = dwc:behavior literals, evidence kinds = lkg:evidenceKind concepts, what was heard = lkg:callType / lkg:callTranscription on the observation (0.6.0; no separate vocalisation node).
  • Regions (0.6.0): an entry links every body-text region it runs through (lkg:hasSourceRegion) and its drawings, maps, photographs, mounted objects and inserted texts (lkg:hasMultimodalRegion → lkg:MultimodalRegion ⊑ SourceRegion).
  • Ziel 1 (0.5.0): on the observation — lkg:spatialContext, lkg:microhabitat, lkg:relativeElevation, lkg:timeOfDay / lkg:daylightPhase, lkg:observationRadiusMeters (mirrored as dwc:coordinateUncertaintyInMeters), dwc:samplingProtocol, lkg:spatialConfidence. Named sites stay lkg:Place via hasLocality when they differ from entryPlace.
  • Merged spellings sit on the node as skos:altLabel; a merged observation keeps the written taxon name as dwc:verbatimIdentification.
  • One link pattern for every authority (0.6.0): taxa → GBIF, habitats → EUNIS 2012, places → GeoNames + Wikidata, persons → Wikidata + GND, all as skos:exactMatch / closeMatch / broadMatch to an authority record (skos:inScheme lkg:authority_*, skos:notation); no owl:sameAs.
  • Every observation, journey and weather report prov:wasGeneratedBy the run (model, prompt hash, time).

5 · Rerun (Colab notebook 07_full_workflow_colab.ipynb)

  1. Cells 0–1: mount Drive, clone main, install; set RUN_TAG (fresh kg_exports_<tag>), Gemini key from the secret / .env (GOOGLE_API_KEY).
  2. Stages A/B skip themselves when their outputs exist.
  3. Cell 16 pulls the newest pipeline; C1 points caches and review CSVs at Drive (run again after every pull).
  4. C2 smoke test — 25 entries live, read the table.
  5. C3 export-all — extraction → corrections → coverage → QA → linking → resolution → habitat→EUNIS → RDF/JSON-LD → SHACL → DwC-A from one pipeline run → C5 review CSVs. C4 export-dwca alone is optional.
  6. Adjudicate: write y / n into the decision column (link reviews and the four merge CSVs), add rows to value_corrections.csv where needed, point reviewed_csv at the files, rerun C3.

A disconnected browser tab does not stop the runtime; every stage resumes from the Drive caches.

6 · Terms

SHACL
shape constraints over RDF; the export is rejected on any violation, warnings are advisory (e.g. empty entries).
DwC-A
Darwin Core Archive — zipped TSV star schema (event core + extensions) with meta.xml/eml.xml, GBIF's exchange format.
eMoF
OBIS ExtendedMeasurementOrFact — measurements keyed to the occurrence (evidence, call type, count qualifier, breeding evidence, EUNIS habitat type, …).
PROV
W3C provenance: the extraction run as an activity with its software agent (model) and prompt entity.
SKOS
controlled vocabularies (concept schemes) and graded matches to GBIF / EUNIS.
Ziel 1
ontology 0.5.0 extension: fine-grained space and time on the observation (vantage, microhabitat, elevation, time-of-day, radius, sampling protocol).
GBIF match
species/match API; EXACT ≥ 90 → exactMatch, FUZZY ≥ 95 → closeMatch, higher rank → broadMatch.
